# 功能详解

EchoRead 把「收藏文章」拆成一条完整的认知内化流水线：从收入内容、AI 研磨，到对话深挖、记忆沉淀、语义检索，每一步都围绕「把高手干货复刻成你的脑资产」展开。下面按七大能力逐一介绍。

## 内容管理

通过 URL 收入文章，自动解析成干净的 Markdown 存进本地知识库，并由 AI 做一轮「认知研磨」。

**特性**

- 支持微信公众号文章、普通网页链接等，服务端提取为 Markdown。
- 保存时可附一段「收藏意图」（为什么要存这篇），帮 AI 结合你的动机去理解。
- AI 自动研磨，为每篇文章产出结构化洞察：一句话本质摘要、核心观点、针对你身份的观察、可落地行动建议、精准标签。
- 收藏后会自动与其他文章寻找跨文关联，并生成语义向量织入晶格。
- 全部数据存在本地 SQLite，本地优先。

**研磨产物**

| 字段 | 说明 |
|------|------|
| 摘要 | 一句话讲清这篇文章的本质 |
| 核心观点 | 3 条左右底层逻辑 / 独特洞察 |
| 观察 | 透过你的用户画像给出的独到视角 |
| 行动建议 | 可落地的下一步动作 |
| 标签 | AI 自动打的精准标签 |

::: tip 想看研磨全流程
文章内化的进度条会依次走过：研磨 → 关联寻觅 → 生成语义向量织入晶格 → 成功入库。其中「语义向量」一步需要配置智谱 Key，没配时会显示「已略过」但不影响其他环节。
:::

## Stitch AI 对话

Stitch 是 EchoRead 内置的 AI 认知助手，它了解你收藏的所有文章，可以和你深度对话，并在三种模式间自动切换。

**三种对话模式**

Stitch 会在回复中隐式判断当前对话形态，自动切到合适的模式：

| 模式 | 触发时机 | 行为 |
|------|----------|------|
| 沉浸（Immersion） | 你专注聊一个话题 | 深入挖掘不跑题，不主动翻旧账 |
| 链接（Linking） | 你开始跨话题联想 | 检索相关的历史碎玉、文章，融入回答 |
| 结晶（Crystallization） | 某主题碎玉密度够高 | 主动提议把碎玉融合为永久认知卡片 |

::: tip 模式由 AI 自动判断
你不需要手动切模式。Stitch 根据每轮对话内容判断该用哪种，在幕后决定要不要调记忆、要不要做跨文联想、要不要提议结晶。
:::

**对话技巧**

- 「我最近收藏了什么？」— 查看近期文章
- 「这些内容对我的主业有什么启发？」— 跨文章综合分析
- 「我之前对 XX 说过什么？」— 召回历史记忆
- 直接就某篇文章提问 — AI 会阅读全文并回答
- 「这篇还有什么类似的？」— 让 AI 基于语义找相关文章

**AI 可调用的工具**

Stitch 在对话中可以按需调用一批工具来读取你的知识库，所以它「知道」你存过什么、聊过什么：

| 工具 | 作用 |
|------|------|
| query_articles_by_date / query_recent_articles | 按日期或最近 N 天查文章 |
| read_article_content / read_article_insight | 读文章全文或 AI 洞察 |
| search_articles | 关键词搜索（标题 + 摘要） |
| semantic_search / find_related_articles | 语义检索 / 查找相关文章（需智谱 Key） |
| query_snippet_lattice | 检索相关碎玉（链接模式） |
| capture_dialogue_snippet | 捕获高光碎玉 |
| save_memory / update_memory / delete_memory / search_memories | 记忆系统的增删改查 |

## 认知晶格

认知晶格是 EchoRead 的核心创新，帮你把碎片化的对话高光沉淀为结构化的永久认知资产，分「碎玉」和「结晶」两层。

### 碎玉

对话中的高光时刻会被自动捕获为「碎玉」——一段值得长期记住的原话或洞察。

- **自动捕获**：AI 识别到你强共鸣（如「太好了 / 就是这样 / 记下来」）时自动记下。
- **主动捕获**：你直接说「记下来」也能触发。
- **语义互连**：每张升格碎玉生成向量后，相似度 ≥ 0.75 的碎玉会自动连成「语义晶格连接」，为结晶铺路。
- **不喧宾夺主**：AI 捕获碎玉后不会在正文里说「我记下了」，保持对话流畅。

### 结晶

当某个主题积累了 **4 张以上**同主题的高引力碎玉，密度达到临界，AI 会提议把它们「结晶」为一张永久认知卡片。

- 结晶卡会写清楚这些碎玉「为什么聚在一起」「共同指向什么认知」。
- 结晶形成后，AI 会建议一条**具体、可在 30 天内完成**的行动，让认知真正落地。

**触发条件**

| 信号 | 阈值 |
|------|------|
| 同主题碎玉数 | ≥ 4 张 |
| 触发动作 | AI 主动提议结晶 + 起标题 + 写综合理解 |
| 结晶后 | 提议一条 30 天内可完成的行动 |

## 记忆系统

记忆系统让 AI 越用越懂你，记住你的身份、偏好、关注主题和跨文洞察，下次对话时能主动召回。

**记忆类型**

| 类型 | 含义 | 例子 |
|------|------|------|
| user | 你的身份 / 角色 | 「我是一名独立开发者」 |
| feedback | 互动偏好 / 纠正 | 「回答尽量简短」 |
| project | 关注主题 | 「最近在研究 Agent 架构」 |
| reference | 跨文洞察 | 你在对话中形成的跨文章认知 |

**特性**

- **自动提取**：每次会话结束（至少 3 条用户消息时），AI 会回顾对话，把值得长期记的认知写进记忆库；不是碰运气的猜测，而是由模型决定是新增、更新还是删除。
- **主动召回**：回答「我之前对 XX 的看法」「你记得我说过什么」前，AI 会先查记忆库。
- **可被遗忘**：你说「忘记 XX」时，AI 会删掉对应记忆；没确认的猜测不会主动记。
- **本地存储**：所有记忆存在本地数据库。

::: tip 记忆 ≠ 对话历史
记忆是跨会话的长期认知，不是把每句对话都存下来。它只保留身份、偏好、关注主题和跨文洞察这类「下次还有用」的信息。
:::

## 语义搜索

基于向量语义的智能检索，不局限于字面匹配，能找到「意思相近」的文章。

**特性**

- **语义召回**：搜索词不必出现在文章里，只要语义相关就能命中。
- **信号密度优先**：向量化输入用标题 + 摘要 + 核心观点 + 标签 + 观察 + 收藏意图，而不是全文，信号更强、速度更快。
- **本地实时计算**：余弦相似度在本机实时算，几篇到上百篇文章都够用。
- **跨文联想**：可基于一篇文章找它的相关文章；碎玉之间相似度 ≥ 0.75 会自动连边。

**两种检索方式对比**

| 维度 | 关键词搜索 | 语义搜索 |
|------|-----------|----------|
| 原理 | 标题/摘要字面匹配 | 整体语义相似度 |
| 例子 | 搜「时间管理」只命中含该词的 | 搜「如何高效安排一天」也能找到讲时间管理的 |
| 依赖 | 即开即用 | 需智谱 Key + 文章已生成向量 |

**启用前提**

语义搜索依赖智谱 embedding-3 模型，需在 **我的 → AI 引擎配置** 填入智谱 API Key。没配 Key 时这一环会跳过，但研磨、对话、记忆等其他功能不受影响（它们由 DeepSeek 提供）。

::: tip 给历史文章补向量
配置 Key 之前收藏的老文章没有向量。开发者工具里的「Embedding 补齐」可以一键为所有 pending/failed 状态的历史文章批量生成向量。
:::

## 用户画像

在「我的」里填写你的职业、关注领域、当前项目等，AI 研磨文章时会透过你的视角去理解内容，给出和你强关联的洞察，而不是放之四海而皆准的摘要。

**画像的价值**

| 场景 | 没有画像 | 有画像 |
|------|----------|--------|
| 收藏一篇系统设计的文章 | 通用摘要 | 开发者看到「架构解耦」，产品经理看到「业务边界」 |
| 跨文综合 | 泛泛而谈 | 围绕你的主业和项目串联 |

画像作为「用户认知 Profile」参与研磨，也喂给对话和记忆系统，让 AI 始终带着你的背景去思考。

## AI 引擎配置

EchoRead 的智能能力由两个 AI 引擎分工提供，都可以在 **我的 → AI 引擎配置** 里自定义。

| 引擎 | 职责 | 默认 | 可否自定义 |
|------|------|------|-----------|
| DeepSeek | 对话 + 文章研磨 | 官方提供默认 Key，开箱即用 | 可填自己的 Key 和模型名 |
| 智谱 embedding-3 | 语义向量化 / RAG | 需自行填入 Key | Key 必填，否则语义搜索失效 |

**可配置项**

| 配置 | 说明 |
|------|------|
| DeepSeek API Key | 对话与研磨用，留空走官方默认 |
| DeepSeek 模型名 | 默认 `deepseek-v4-flash`；研磨任务用更强的 `deepseek-v4-pro` 保证质量 |
| 智谱 API Key | 向量化/RAG 用，从智谱开放平台获取，费用自理 |

::: tip 两个引擎各管一摊
DeepSeek 负责所有「理解 + 生成」类任务（研磨、对话、记忆提取），智谱只负责把文本变成向量做相似度计算。所以即使不配智谱 Key，EchoRead 的核心智能体验完全不受影响，缺的只是语义检索和相关推荐。
:::
