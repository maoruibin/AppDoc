# 盒子

盒子是 inBox 提供的一种笔记归类方式，你可以在 **设置 > 功能** 中找到这个功能的入口。

该功能默认关闭，需要手动打开。

## 盒子是什么

简单说，盒子就是传统笔记软件里的"分类"或"文件夹"。

inBox 本身支持 [标签](tag.md)，可以用 `#标签名` 给笔记打标，标签更自由、可以一条笔记打多个、还可以多级嵌套。

盒子则更严格：

- **一条笔记只能属于一个盒子**（或者不属于任何盒子）
- 盒子是有意为之的"大类"，比如可以建一个盒子专门放密码、再建一个放个人重要信息
- 盒子主要用来收纳"长期有用、需要归类"的内容

标签是横向的（一条笔记多个标签），盒子是纵向的（一条笔记一个归属）。两者并不冲突，可以同时用。

## 为什么需要盒子

inBox 的设计初衷是"低门槛记录灵感"，所以默认不强求分类，所有笔记都在一起，需要找的时候用标签或者搜索。

但用得久了，会逐渐发现有些笔记其实是有"归属感"的：

- 账号密码、密保问题 → 想归到一起，方便找
- 体检报告、病历 → 长期重要，不想跟日常灵感混在一起
- 读书摘录 → 想集中管理

用标签可以做到，但标签太自由，容易随手就打、随手就忘。盒子强制"只能选一个"，反而让分类更清晰、更有结构。

简单说：**标签适合"模糊归类"，盒子适合"明确归属"**。

## 如何使用

### 打开盒子功能

进入 **设置 > 功能**，打开"盒子"开关。

打开后，主页最顶部 inBox 名称旁边会出现一个三角符号，点击可以展开盒子面板。

### 新建盒子

在盒子面板里点"新建盒子"，输入名字即可。

盒子名支持中文、英文、数字，以及部分符号（会自动替换掉不能用作文件夹名的字符，比如 `/ \ : * ? " < > |`）。

### 给笔记归类

在写笔记或编辑笔记时，可以从笔记顶部选择把它放进哪个盒子。一条笔记只能选一个盒子。

放进盒子后，笔记顶部会显示盒子名，点击盒子名可以快速跳转到这个盒子的笔记列表。

### 重命名盒子

在盒子面板长按某个盒子（或点击编辑），可以重命名。重命名后：

- inBox App 内：所有该盒子下的笔记会同步更新归属名
- [Obsidian 插件](plugin_obsidian.md) / [思源插件](plugin_siyuan.md)：下次同步时，本地对应的文件夹会自动重命名，笔记 frontmatter 里的 `box` 字段也会更新

### 删除盒子

长按盒子，选择删除。

删除盒子不会删除盒子里的笔记，只是把盒子本身移除：

- inBox App 内：原盒子下的笔记会变成"无盒子"状态
- Obsidian / 思源插件：下次同步时，本地对应文件夹下的笔记会被移回根目录，文件夹清空后删除

> 删除是"软删除"，盒子清单里会保留一条墓碑记录（`deleted_at` 字段），保证其他端的同步能正确识别"这是删除"而不是"这是新建"。

## 盒子与同步

盒子信息独立存储在云端 `boxes.json` 文件里，每次同步开始时插件会先拉这个清单，构建 `boxId → 盒子名` 的映射。

笔记的盒子归属存在 atomicNote 的 `content.box_id` 字段（稳定 ID，跟盒子名解耦，盒子改名不影响归属）。

如果你使用 [Obsidian 插件](plugin_obsidian.md) 或 [思源插件](plugin_siyuan.md)，盒子会自动映射为本地文件夹：

- 有盒子的笔记 → 同步到 `<盒子名>/` 子文件夹
- 无盒子的笔记 → 同步到根目录

详见对应插件文档。

## QA

### 盒子和标签我应该用哪个？

两个都用。标签适合随手打、做横向主题归类（比如 `#工作`、`#灵感`、`#读书笔记`）；盒子适合做纵向的内容归属（比如"密码"、"健康记录"这类长期重要、单一归属的内容）。

### 一条笔记可以属于多个盒子吗？

不可以。这是盒子跟标签的核心区别。

### 删除盒子后，盒子里的笔记会怎样？

笔记不会丢，只是变成"无盒子"状态。在 inBox App 里笔记还在，在 Obsidian / 思源插件里笔记会被移到根目录。

### 我重命名了盒子，插件端的文件夹会跟着改吗？

会。下次同步时，插件检测到盒子名变化，会自动 rename 文件夹，笔记 frontmatter 里的 `box` 字段也会更新。详见各插件文档。
