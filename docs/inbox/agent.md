# AI Agent 接入

inBox 笔记支持让 AI 编程助手（如 Codex、Claude Code、Cursor）直接读写你的笔记。

配置完成后，你可以对着 AI 说「今天记了什么笔记」「帮我搜一下关于 Flutter 的笔记」「帮我记一条笔记」，AI 会自动查询或写入，不需要手动翻 App。

## 怎么用

整个过程只需要三步。

### 第 1 步：打开 Agent 接入页

在 App 内进入 **数据中心 → Agent 接入**。

如果你已经配置了云盘（WebDAV 或 S3），页面会自动生成一段提示词。

### 第 2 步：一键复制

点击「一键复制配置」，提示词会复制到剪贴板。这段提示词里包含了你的云盘配置信息，AI 拿到后能自动完成全部安装。

### 第 3 步：发给 AI

打开你常用的 AI 编程助手（Codex、Claude Code、Cursor 等），把提示词粘贴进去，发送。

AI 会自动完成安装 CLI、配置云存储、安装技能、验证连接，全程不需要你手动敲命令。

连接成功后，AI 会告诉你笔记总数，然后就可以开始用了。

## AI 能做什么

连接成功后，你可以用自然语言让 AI 操作笔记：

| 你说的话 | AI 会做的事 |
|----------|------------|
| 今天记了什么笔记？ | 查询今天的笔记列表 |
| 搜一下关于 Flutter 的笔记 | 按关键词搜索标题、正文、标签 |
| 帮我记一条笔记：xxx | 创建一条新笔记 |
| 帮我修改那条笔记 | 更新笔记内容 |
| 删掉那条笔记 | 软删除（可在回收站恢复） |
| 我有哪些标签？ | 列出所有标签及使用次数 |

读取笔记时 AI 会直接执行，不用问你。写入笔记（创建、修改、删除）时，AI 会先把操作内容展示给你看，你确认后才执行。

## 支持哪些 AI 工具

任何能执行终端命令的 AI 编程助手都可以用：

- **Codex**（OpenAI）
- **Claude Code**（Anthropic）
- **Cursor**
- 其他支持执行 shell 命令的 AI Agent

## 工作原理

inBox Agent 接入通过一个命令行工具（`gudong-inbox`）连接你的云存储，读写笔记数据。每个命令都是独立的进程，跑完就退出，不需要常驻后台服务。

这和 MCP 方案的区别在于：MCP 需要启动一个持久运行的服务进程，配置复杂，出错难排查。而 CLI 方案是即用即走，任何 AI 都能直接调用，简单可靠。

```
AI 编程助手（Codex / Claude Code / Cursor）
        ↓ 执行命令
  gudong-inbox（命令行工具）
        ↓ 读写 JSON
  你的云存储（WebDAV / S3）
        ↓ 同步
  inBox App
```

笔记数据始终存储在你自己的云盘里，CLI 只是读取同一份数据，不经过任何中间服务器。

## 常见问题

### 提示词里的密码安全吗？

提示词里包含你的云盘配置信息（账号、密码或密钥），这些信息只在你的设备上生成并复制。发送给谁由你自己决定。建议只在信任的 AI 工具中使用。

### 手机上能用吗？

AI Agent 接入主要面向电脑端使用（AI 编程助手通常运行在电脑上）。手机端负责生成配置提示词，电脑端的 AI 负责执行。

### 和 API 有什么区别？

- **API**：通过一个 URL 地址向 inBox 写入笔记，适合自动化脚本和浏览器插件，需要注册账号，有频率限制（每天 50 条）
- **Agent 接入**：直接读写云端笔记数据，功能更全面（读、写、搜、删），不限频率，不需要注册账号，但需要在电脑上使用 AI 编程助手

### 配置失败怎么办？

检查以下几点：
- 云盘是否配置正确（在数据中心测试同步是否正常）
- 网络是否能访问云存储地址
- 把 AI 显示的错误信息原样反馈，它会帮你排查
