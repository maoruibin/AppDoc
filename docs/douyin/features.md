# 功能详解

抖音保存围绕"粘贴口令 → 解析 → 下载"这条主链路把每个环节做扎实。下面按功能模块拆开介绍，包括背后的实现原理和可选项。

## 视频解析

### 解析流程

抖音保存的解析不依赖脆弱的分享页抓取，而是基于成熟的 [yt-dlp](https://github.com/yt-dlp/yt-dlp) 工具走抖音 web 详情 API，比解析分享页更稳定。整体流程：

1. 从用户粘贴的文字里提取出抖音链接（短链或长链都能识别）。
2. 调用内嵌的 yt-dlp，带上 Chrome 浏览器的 cookie 去请求抖音。
3. yt-dlp 返回一条 JSON，里面包含标题、作者、封面、formats 列表等完整信息。
4. 从 formats 里找到 `format_id == "play_addr"` 的那条，就是无水印视频地址。

这条链路对用户透明——你只要粘贴口令、点解析，剩下的 App 自动搞定。

### 支持的链接格式

App 会从粘贴的整段文字里自动挑出链接，下面几种都能识别：

| 链接类型 | 示例 | 说明 |
|----------|------|------|
| 抖音短链 | `https://v.douyin.com/iAbCdEf/` | 分享口令里最常见的格式 |
| 长链（douyin.com） | `https://www.douyin.com/video/xxxxx` | 浏览器里复制的网页链接 |
| 旧版长链（iesdouyin.com） | `https://www.iesdouyin.com/share/video/xxxxx` | 早期分享链接，同样支持 |

直接把整段分享口令（带描述文字、emoji、前后数字）粘进去也行，App 会用正则把链接提取出来。

### 为什么需要 Chrome cookie

抖音的视频信息接口需要登录态才能正常返回。App 通过 `--cookies-from-browser chrome` 让 yt-dlp 读取本机 Chrome 浏览器里已登录的抖音 cookie，相当于"借"了你浏览器的登录身份去请求。

所以使用前需要在 Chrome 浏览器里登录过抖音（[douyin.com](https://www.douyin.com)）。如果 cookie 失效或 Chrome 没登录，解析会失败并提示重新登录。

## 无水印下载

### 无水印地址

抖音返回的视频信息里有多条 format，其中 `format_id == "play_addr"` 的那条是无水印的原始播放地址。下载时 App 显式指定 `-f play_addr`，确保拿到的是干净版本，不会带平台水印。

| 参数 | 值 | 说明 |
|------|------|------|
| 下载格式选择 | `play_addr` | 无水印视频流 |
| 防盗链处理 | yt-dlp 自带 | 自动设置 Referer / UA，无需手动配置 |
| cookie 来源 | Chrome 浏览器 | 和解析用同一套登录态 |

### 下载进度

下载过程是实时反馈的。yt-dlp 通过 `--progress-template` 输出每一行的字节数，App 解析后换算成 0–100% 的进度：

- 解析完成的瞬间，结果卡片下方出现进度条。
- 每收到一段数据，进度条和百分比文字同步刷新。
- 进度走到 100% 后按钮变成「已保存到下载文件夹」，并显示完整保存路径。

如果中途出错（比如网络断开、抖音拒绝请求），进度会停在原地，App 把友好的错误提示弹出来，不会留下一个半截文件让人摸不着头脑。

## 图文类型识别

抖音除了视频还有「图文」内容——多张图片配背景音乐轮播。抖音保存会自动识别这种类型：

- 解析结果里如果**有视频地址**，标记为「视频」。
- 如果**没有视频地址但有图片列表**，标记为「图文 N 张」（N 是图片数量）。

结果卡片上用不同的图标区分：视频是播放图标，图文是相册图标，并标注具体张数，让你一眼看出这条内容的类型。

## 多平台支持

抖音保存用 Flutter 构建，一套代码同时覆盖移动端和桌面端：

| 平台 | 支持 | 说明 |
|------|------|------|
| Android | 支持 | 主力平台，完整功能 |
| iOS | 支持 | 完整功能 |
| macOS | 支持 | 桌面端，宽屏自适应布局 |
| Windows | 支持 | 桌面端，宽屏自适应布局 |

桌面端打开后，内容会自动限宽居中（最大宽度 480），不会在大屏上拉得过宽。解析、下载的操作流程和移动端完全一致。

底层依赖的 yt-dlp 二进制文件会跟着 App 一起打包：

| 平台 | 内嵌位置 | 加载方式 |
|------|----------|----------|
| macOS | App bundle 的 `Contents/Resources/` | 首次运行复制到 ApplicationSupport 目录并设可执行权限，避开签名/quarantine 限制 |
| Windows | 和 exe 同级目录 | 直接调用 |
| 开发环境 | 系统 PATH | 开发调试时用本机安装的 yt-dlp |

## 本地存储

### 保存位置

下载完成的文件统一保存到系统的**下载目录**：

| 平台 | 下载目录 |
|------|----------|
| Android | 系统下载文件夹（`Download/`） |
| iOS | App 沙盒内的下载目录 |
| macOS | 用户的 `~/Downloads` |
| Windows | 用户的下载文件夹 |

下载完成后，结果卡片会显示完整的保存路径，方便直接去文件管理器里找。

### 文件命名

文件名直接用视频的标题，这样保存下来一堆文件时一眼能看出是什么内容。命名时做了这些清理：

| 处理 | 说明 |
|------|------|
| 去非法字符 | 把 `\ / : * ? " < > \|` 和换行等不能当文件名的字符替换成空格 |
| 去分享口令前缀 | 自动去掉标题开头的分享数字（如「7.69 」） |
| 压缩连续空格 | 多个空格合并成一个 |
| 长度截断 | 标题超过 80 字符时截断，避免文件名过长 |
| 兜底命名 | 标题为空时用 `douyin_<时间戳>` 保证有文件名 |

文件扩展名由 yt-dlp 根据实际下载的视频格式自动决定（通常是 `.mp4`）。
